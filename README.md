# 업체별 업무 일정 · D-day 도우미

업체별로 공사·업무의 절차 기한을 놓치지 않게 하는 Windows 데스크톱 앱입니다.

**이 앱에는 창이 없습니다.** 열고 닫을 프로그램 창 대신, 세 조각이 바탕화면에
붙어 삽니다 — 배경화면에 심어진 **달력 시트**, 급한 일정과 검색·추가를 담은
**미니 대시보드**, 행사·예산 요약인 **현황**. 입력 폼과 상세만 작은 창으로
잠깐 열렸다 닫히고, 종료와 조각 보이기/숨기기는 트레이 아이콘이 맡습니다.

이 앱의 목적은 '관리'가 아니라 **누락 방지**입니다. 업체 N개 × 공사 M개 × 절차 8단계가
동시에 굴러가는 상황에서 기한을 놓치지 않는 것이 전부이고, 그래서 진척률·KPI·차트처럼
시스템이 실제로 알 수 없는 것을 만들어내는 표시는 의도적으로 넣지 않습니다.

제품 요구사항의 근거는 [`CODEX_IMPLEMENTATION_BRIEF.md`](CODEX_IMPLEMENTATION_BRIEF.md)와
[`AGENTS.md`](AGENTS.md)에 있습니다. 코드를 고치기 전에 두 문서를 먼저 읽으세요.

## 화면 구성

| 조각 | 답하는 질문 | 규칙 |
|---|---|---|
| 달력 시트 | 이번 달이 어떻게 생겼나 | 월 격자가 창을 꽉 채운다(스크롤 없음). 빈 날짜 두 번 클릭=일정 추가, 일정 클릭=상세, 끌어서 날짜 이동 |
| 미니 대시보드 · 일정순 | 지금 뭐가 급한가 | 기간 안의 미완료 건을 **하나도 묶지 않고** 날짜순으로. 색이 긴급도를 구분한다 |
| 미니 대시보드 · 업체별 | 이 업체는 지금 어디까지 왔나 | 진행률·지연·가장 가까운 일정, 펼치면 업무별 |
| 미니 대시보드 · 검색 칸 | 어디에 있더라 / 바로 적자 | 업체·행사·업무·일정·지출 5종 검색 + 그 이름 그대로 일정 만들기 |
| 현황 · 행사별 | 이 행사에 누가 참여하고 어디까지 왔나 | 누르면 참여 업체·진행률·지출로 펼쳐짐 |
| 현황 · 예산 | 어디에 얼마가 나갔나 | 누르면 예산항목 → 행사 → 업체로 펼쳐짐 |
| 상세 (pop 창) | 지금까지 뭘 했고 다음은 뭔가 | 업무 기록, 첨부, 지출, 절차 전단계 |

조각은 전부 **바탕화면 악세사리**입니다. 제목표시줄이 없고, 작업표시줄에 뜨지
않고, 다른 프로그램 **아래**(바탕화면 쪽)에 깔립니다. 머리 부분을 잡아 끌면
움직이고 그 자리를 기억합니다. `바탕화면 보기(Win+D)` 를 눌러도 사라지지
않습니다. 트레이 아이콘에서 조각을 보이고 숨기고, 앱을 끝냅니다.

왼쪽 바탕화면 아이콘 한 열(96px)은 비우고 자리를 잡습니다 — 휴지통을 포함한 첫 열을
덮어 누를 수 없게 만들던 것을 고쳤습니다. 머리 왼쪽 여섯 점이 끌기 손잡이입니다.

키보드: `T` 오늘 · `←→` 달 이동 · `N` 일정 추가(달력·미니에서만) · `/` 검색.
입력 중이거나 폼이 떠 있으면 아무것도 가로채지 않습니다.

24시간 켜 두는 위젯이므로 자정에 스스로 다시 그립니다. 절전에서 깨어난 경우를 위해
1분마다 날짜만 대조합니다 — 하루가 지났는데 화면이 어제에 멈춰 있으면 누락이 가장
잘 나는 그 하루에 정확히 틀립니다.

`업체 / 업무 / 절차 / 일정`이라는 이름은 고정이 아닙니다. `템플릿 → 용어·항목`에서
바꾸면 화면 전체에 반영되고, 한국어 조사(은/는, 이/가, 을/를, 과/와, 으로/로)도
받침에 맞춰 자동으로 골라집니다. 기존 데이터는 그대로 유지됩니다.

### 칸이 좁아지면 물러난다

달력 칸의 실제 폭을 재서 표기 수준을 정합니다 — 170px 이상이면 「업체 · 업무」,
110px 이상이면 업무명만, 그 아래는 글자를 버리고 **점과 건수**로 갑니다.
84px 칸(1024×768 화면)에 13px 한글은 두 글자밖에 담기지 않아, 같은 규칙을 밀어붙이면
「동… D+4」가 됩니다. 점을 누르면 그 일정이 열리고, `＋N건`·완료 체크를 누르면
그 날 목록이 열립니다.

완료한 일정은 칸 안 줄을 버리고 날짜 옆 **초록 체크**로 접힙니다. 데이터가 쌓일수록
완료 건 비율은 단조롭게 올라가기만 하는데, 숨길 방법이 없었습니다.

### 절차 사슬 — 예상 마감

업무를 등록하면 첫 단계에만 날짜가 붙고, 완료할 때마다 바로 다음 한 건에만 날짜가
생겼습니다. 절차 템플릿은 단계마다 간격(`+2일 +3일 +20일`)을 이미 갖고 있는데 첫 단계
말고는 쓰지 않아서, **업무당 미래 마감이 언제나 정확히 1건**이었습니다. 3주 뒤 계약
마감이 다가오는지 알 방법이 없었고, 그게 없으면 이 앱은 '업체 이름이 붙는 달력'입니다.

이제 간격을 누적해 뒤 단계의 **예상 마감일**을 산출하고 점선 칩으로 미리 깝니다.
앞 단계를 실제로 완료하면 그 완료일을 기준으로 뒤 날짜가 저절로 당겨지거나 밀립니다.

계산만 하고 **저장하지 않습니다.** 상태를 건드리지 않으므로 마이그레이션도, 되돌리기
충돌도, '사용자가 넣은 날짜인지 자동 계산인지' 구분 문제도 생기지 않습니다.
예상은 추측이므로 급한 일 목록과 `지남 N` 카운트에는 넣지 않고 긴급도 색도 칠하지
않습니다 — 추측으로 빨강을 칠하면 그건 거짓 경보입니다.

### 근무일과 비근무일

행정 마감은 근무일에 걸립니다. 마감일이 토·일·공휴일이면 실제로는 그 앞 근무일까지
끝내야 하는데, 공휴일 개념이 코드에 아예 없었습니다. 관보 기준 2025~2028년 공휴일
표를 앱에 동봉했습니다(파일을 읽지 않습니다 — 발주서 §26 의 임의 경로 접근이 아닙니다).
토요일은 파랑, 일요일과 공휴일은 빨강이고 칸에 공휴일 이름이 뜹니다.

색은 시간 긴급도에만 씁니다 — 파랑(예정) → 주황(오늘) → 빨강(지남).
초록은 완료에만 씁니다. 예산에서도 같은 규칙입니다 — 기지출은 집행이
끝난 돈이라 초록, 지출예정은 파랑, 잔액은 회색, 초과는 빨강입니다.

### 기간

일정에 **종료일**을 주면 행사참여기간·접수기간처럼 기간이 있는 일이 됩니다.
캘린더에 시작~종료가 이어진 띠로 보이고, D-day 는 시작 전 `D-n` → 기간 중
`진행중` → 종료 후 `D+n` 으로 바뀝니다. 진행 중인 건은 D-day 기준을 좁혀도
좌측 레일에서 사라지지 않습니다. 업무(행사)에도 전체 기간을 줄 수 있고,
그것은 날짜 칸 위쪽 띠로 따로 그려집니다.
절차 단계에는 기간이 없습니다 — 절차는 본질적으로 마감일입니다.

### 행사와 참여 업체

한 행사에 업체 여러 곳이 참여합니다. 업무는 **'업체 × 행사' 참여 건**이고,
그 위에 **행사**가 있습니다. 캘린더 띠는 참여 업체가 몇 곳이든 한 줄이고,
예산의 '행사별'도 행사 단위로 묶입니다.

**업체마다 참여기간이 다를 수 있습니다.** 한 달짜리 행사에 A·B 는 한 달 쭉,
C 는 2주만 참여하는 경우가 그대로 담깁니다. 한 곳을 줄여도 행사 기간은
바뀌지 않습니다.

중간에 업체가 더 들어오면 현황의 `행사별` 을 펼치고 그 행사 줄에서
`+ 참여 업체 추가` 를 누릅니다. 목록에 없는 업체는 거기서 바로 만듭니다.

### 업체를 고르는 방식

업체가 나오는 모든 칸은 **검색되는 칸**입니다. 글자를 치면 걸러지고, 목록에
없으면 맨 아래 `‘○○’ 새 업체로 만들기` 가 나옵니다. ↑↓·Enter·Esc 로
마우스 없이 끝납니다. 행사·예산항목·업무도 같은 방식입니다.

### 여러 업체에 같은 일정

`일정 추가` 에서 업체를 여러 곳 고르면 **업체 수만큼 일정이 따로** 만들어집니다.
기간은 위에 적은 공통값이 기본이고, 아래 `업체별로 다르게` 에서 한 줄만 고치면
그 업체만 달라집니다(`공통으로` 로 되돌릴 수 있습니다).
만들어진 뒤에는 완료·기록·첨부·삭제가 전부 따로 됩니다 — 묶여서 잠기지 않습니다.

### 지울 때

지우면 먼저 지우고 **되돌리기**를 6.5초 띄웁니다. 확인창은 되돌려도 복구가 안 되는
다섯 곳에만 남았습니다(예산 감액·용어 기본값·절차 단계 삭제·백업 복원·예산항목 삭제).
첨부 실물은 되돌리기 창이 닫힌 뒤에 지웁니다 — 먼저 지우면 되돌려도 파일이 없습니다.

### 업체·업무·일정 한 번에

`업무 추가` 하나로 끝납니다. 업체는 검색되는 칸에서 고르거나 없는 이름을 쳐서
그 자리에서 만들고, 행사를 고르면 그 기간이 참여기간 기본값으로 들어옵니다.
업무 템플릿을 `없음`으로 두면 업체와 일정만 등록됩니다.
아래 `함께 등록할 일정`에 여러 줄을 적으면 한 번에 들어갑니다.

### 예산

`템플릿 → 용어·항목`에서 이름을 바꿀 수 있는 것처럼, 예산도 도메인 용어를
따릅니다. 합본예산서는 현황의 `예산` 을 펼쳐 `합본예산서` 에서 항목·예산액을
넣습니다. 지출은 예산 화면과 **일정 상세** 두 곳에서 등록합니다 — 계약·준공
단계에서 그 자리에 금액을 적을 수 있어야 예산 화면을 따로 찾아갈 일이 없습니다.

> 합본예산서를 파일에서 가져오는 기능은 아직 없습니다. 실제 예산서 형식을
> 확인한 뒤에 붙일 예정입니다. 지금은 손입력입니다.

## 실행

### 웹으로 바로 보기

`web_standalone.html`을 Chrome/Edge에서 엽니다. 저장소 안에서 열어야 폰트가 함께 잡힙니다.
브라우저에서는 세 조각이 한 페이지에 함께 렌더됩니다(동작은 데스크톱과 같습니다).

> 이 파일은 `frontend/`에서 생성된 결과물입니다. 직접 고치지 말고 아래 빌드 명령을 쓰세요.

### 데스크톱(Tauri) 개발 실행

Rust와 Node.js가 설치된 환경에서:

```bash
npm ci
npx tauri dev
```

### Windows 설치파일 빌드

설치파일은 **관리자 권한(UAC)을 요구하지 않습니다.** `installMode: currentUser`로
`%LOCALAPPDATA%`에만 설치됩니다 — 관리 대상 관공서 PC에서 이게 결정적입니다.
WebView2가 없는 PC를 위해 부트스트래퍼를 설치파일에 담았습니다(+1.8MB).
인터넷이 아예 없는 망에 배포해야 하면 `tauri.conf.json`의 `webviewInstallMode`를
`offlineInstaller`로 바꾸세요(+127MB).


```powershell
.\build_windows.ps1
```

결과물: `src-tauri\target\release\bundle\nsis\*.exe`

GitHub Actions(`.github/workflows/windows-build.yml`)에서도 같은 빌드를 돌립니다.
`main` 또는 `claude/**` 브랜치에 push하면 실행되고, NSIS 설치파일이
`work-calendar-helper-windows-x64` artifact로 올라갑니다.

## 개발

```bash
npm ci                      # 의존성 (Playwright만)
npm run check               # JavaScript 구문 검사
npm run build:standalone    # frontend/ -> web_standalone.html
npm test                    # 브라우저 스모크 테스트 (350건+)
npm run test:e2e            # Windows 실동작 E2E (Windows + tauri-driver 필요)
```

`npm test`는 Chromium으로 화면을 실제로 조작합니다. `tauri.conf.json`과 같은 CSP를
응답 헤더로 실어 보내고, 렌더된 모든 글자 크기를 실측해 13px 하한을 지킵니다.

`npm run test:e2e`는 **빌드된 실물 앱을 띄워 조작**합니다. 브라우저로는 확인할 수 없는
것들 — 앱 폴더에 파일이 실제로 생기는지, 껐다 켜도 첨부가 남는지, 자동 실행이
레지스트리에 들어가는지, 조각 창 세 개가 실제로 뜨는지, pop 창이 열리는지,
창 위치가 복원되는지, 실제 WebView2에서 CSP 위반이 없는지 — 를 확인합니다.
CI의 `windows-e2e` 잡이 돌립니다.

### 소스 구조

```

                     ?w=cal|mini|status|pop 파라미터로 창마다 필요한 조각만 렌더
  core.js            상태·저장·마이그레이션·날짜 계산·검색
  app.js             화면 UI (조각·팝·드래그·키보드)
  styles.css         디자인 토큰 + 전체 스타일
  fonts/             Pretendard Variable (동봉)
  zip.js             의존성 없는 ZIP 읽기/쓰기 (백업용)
  combobox.js        검색되는 선택 칸 (W3C APG 콤보박스, 의존성 0)
src-tauri/           Tauri 2 네이티브 셸 (조각 3창·트레이·pop 창), 아이콘, NSIS 설정
  capabilities/      default.json(공통) + main.json(앱 폴더 파일 권한)
tools/               build-standalone.mjs, make-icons.mjs
tests/
  smoke.mjs          브라우저 스모크 테스트
  e2e.mjs            Windows 실동작 E2E (tauri-driver 직접 호출)
  win32.ps1          창 속성·레지스트리 확인 (Win32 직접 호출)
assets/app-icon.svg  앱 아이콘 원본
```

`web_standalone.html`은 생성물입니다.
CI에서 `git diff --exit-code`로 원본과 어긋났는지 검사하므로,
`frontend/`를 고친 뒤 `npm run build:standalone`을 실행하고 함께 커밋하세요.

### 디자인 토큰

`frontend/styles.css`의 `:root`에 색·타입 스케일이 모여 있습니다.
**개별 규칙에서 `font-size`에 px를 직접 쓰지 마세요.** `--fs-xs/sm/md/lg`만 씁니다.

| 토큰 | 값 | 용도 |
|---|---|---|
| `--fs-xs` | 13px | 보조 텍스트 **하한** |
| `--fs-sm` | 15px | 기본 본문, 컨트롤 |
| `--fs-md` | 17px | 업체명, D-day 등 1순위 정보 |
| `--fs-lg` | 19px | 패널·모달 제목 |

13px 하한은 범정부 UI/UX 디자인시스템(KRDS)의 PC 최소 본문(`body-xsmall` 1.3rem)이자
발주서 §19.3의 요구입니다. 스모크 테스트가 렌더된 모든 글자를 실측해 이 하한을 지킵니다.

### 아이콘 재생성

`assets/app-icon.svg`를 고친 뒤:

```bash
npm install --no-save sharp png-to-ico
node tools/make-icons.mjs
```

Rust 툴체인이 있으면 `npx tauri icon assets/app-icon.svg`도 같은 일을 합니다.
NSIS 번들러는 `src-tauri/icons/icon.ico`를 요구하므로 이 파일이 없으면 Windows 빌드가 실패합니다.

## 데이터

데스크톱에서는 전부 앱 전용 폴더 안에 있습니다.

```
%LOCALAPPDATA%\kr.go.goseong.work-calendar-helper\
  work-calendar.json          상태 (Tauri Store)
  attachments\<엔티티id>\      첨부파일 실물
  backups\backup-YYYY-MM-DD.zip   자동 백업 (최근 7개)
```

- 첨부는 **실제 파일**로 저장됩니다. 물리 파일명에는 생성된 id만 쓰고 사용자 파일명은
  메타데이터로만 둡니다. 웹 미리보기에서는 IndexedDB로 대체됩니다.
- 앱은 **자기 데이터 디렉터리 밖을 쓸 수 없습니다.** "사용자가 고른 임의 경로에 쓰기"를
  아예 만들지 않았습니다. 백업 내보내기도 앱 폴더에 쓴 뒤 그 폴더를 탐색기로 열어 줍니다.
- 스키마 버전은 상태의 `version` 필드와 `core.js`의 `migrate()`가 관리합니다.
  저장 키(`work-calendar-state-v5`)는 기존 데이터가 고아가 되지 않도록 고정입니다.
- 최초 실행 시에는 업체·업무 템플릿만 들어갑니다. 예시 공사·일정은
  `설정 → 예시 데이터 불러오기`로 넣고 뺄 수 있고, 실제 데이터는 건드리지 않습니다.

### 백업

**하루 한 번 자동으로 만들어집니다.** 버튼을 눌러야만 백업된다면 사용자가 기억해야 하고,
그러면 잊는 순간 보호가 사라집니다. 앱을 켤 때 마지막 백업이 하루 이상 지났으면 조용히
한 벌 남기고 최근 7개만 보관합니다. **성공은 알리지 않고 실패했을 때만 알립니다.**

ZIP 안에는 상태 JSON과 **첨부파일 실물**이 함께 들어갑니다. `manifest.json`에 첨부를
몇 개 담았고 몇 개가 실물 없이 빠졌는지 기록하므로, 첨부 빠진 백업을 전체 백업으로
착각할 일이 없습니다.

`설정 → 백업`에서 지금 백업 / 폴더 열기 / 목록에서 복원을 할 수 있습니다.
복원은 덮어쓰기 확인을 받고, 복원 직전 현재 데이터를 한 벌 자동으로 남깁니다.
다른 PC에서 가져온 ZIP은 백업 폴더에 넣으면 목록에 나타납니다.

### 알려진 한계

- 웹 미리보기(`web_standalone.html`)에서는 자동 백업이 동작하지 않습니다.
  브라우저는 사용자 몰래 디스크에 쓸 수 없기 때문입니다. 수동 내려받기만 가능합니다.
- 첨부 1개당 50MB 상한이 있습니다.

### 콘솔 창

`src-tauri/src/main.rs` 의 `#![cfg_attr(not(debug_assertions), windows_subsystem = "windows")]`
가 빠지면 릴리스 빌드도 콘솔 서브시스템으로 링크되어, **앱이 살아 있는 내내 검은
콘솔 창이 옆에 남습니다.** 빌드는 성공하므로 초록불만 봐서는 잡히지 않고,
리눅스에서는 아예 드러나지 않습니다. CI 가 빌드된 exe 의 PE 헤더에서
서브시스템 값(2 = GUI)을 직접 읽어 검사합니다.

### 자동 검사로 확인하지 못한 것

`npm run test:e2e` 는 **GitHub Actions 의 windows-latest 러너에서는 돌지 않습니다.**
러너의 비대화형 세션에서 GUI 앱의 WebView2 가 디버깅 포트를 열지 못해
세션 생성이 `DevToolsActivePort file doesn't exist` 로 실패합니다.
그래서 CI 에서는 수동 실행 입력으로만 켜지도록 해 두었습니다.
**실제 Windows PC 에서는 `npm run test:e2e` 가 그대로 동작합니다.**

아래 항목은 설치 후 직접 눌러 확인해야 합니다.

| 확인할 것 | 어디서 |
|---|---|
| 조각 세 개가 바탕화면에 뜨는가 | 설치 후 첫 실행 |
| 조각 머리를 잡아 끌면 움직이고 자리를 기억하는가 | 시트/미니/현황 머리를 끌고 재실행 |
| Win+D(바탕화면 보기) 후에도 조각이 남는가 | Win+D 눌러 보기 |
| 트레이에서 조각 숨김/표시·종료가 되는가 | 시계 옆 트레이 아이콘 |
| 입력 폼이 작은 창으로 열렸다 닫히는가 | 일정 추가·상세 열기 |
| 컴퓨터를 켤 때 조각이 뜨는가 | 설정 → 컴퓨터 시작 시 자동 실행 |
| 첨부가 앱을 껐다 켜도 남는가 | 상세 → 파일 첨부 후 재실행 |
| 자동 백업 ZIP 이 생기는가 | 설정 → 백업 → 폴더 열기 |

나머지 기능(일정 등록, 기간 일정, 절차 진행, OK 완료 → 다음 단계 날짜 계산,
업무 기록, 완료 취소, 템플릿 스냅샷 격리, 용어 변경, 업체·업무·일정 일괄 등록,
예산 집계와 드릴다운, 끌어서 날짜 이동, 5종 검색, 키보드, 백업 왕복, 데이터
이관)은 브라우저 스모크 350여 건으로 확인되어 있습니다.
