# ux-acceptance — §12 흐름 수용 대본

정본: `docs/spec/spec_v2.md:515-548`(§12), `docs/spec/spec_v2_errata.md`(개정), `docs/design/doctrine.md`(U1–U9). 이 스킬은 흐름을 "단계 → 화면 → 문구 → 검증"으로 풀어 쓴 실행 대본이다.

## 절차
1. 구현·테스트 전에 `references/flows.md`에서 해당 흐름의 대본을 읽고, `references/error-prevention.md`의 U 규칙을 적용한다.
2. 각 흐름은 **[제약 입력 → preview → 결과 문장 버튼 → 저장 → undo]** 4단을 갖춰야 한다(되돌릴 수 있는 단일 변경은 preview 없이 즉시 저장 + undo).
3. Playwright 시나리오는 대본의 "검증" 줄을 그대로 assertion으로 옮긴다. 명령 수(클릭+키 입력)를 세어 결과표에 적는다.
4. 통과 기준: 대본의 검증 전부 + 한글 IME 조합 시뮬레이션 + 키보드 전용 경로 + 빈/오류 상태 1개 이상.
5. 실패·미구현은 결과표에 그대로 적는다("동작함" 주장 금지).

## 흐름 요약 (상세: references/flows.md)
| 흐름 | 진입 | 필수 preview | 확정 버튼 문구 | undo |
|---|---|---|---|---|
| 일반 일정 등록(Quick Add) | 위젯→Layer 1→Ctrl+N (3번 이내) | 해석 결과 한 줄 "9월 24일(수) 14:00 · 업체 연결 없음" | 저장(Enter) | 토스트 8초 |
| 업체 등록 | 캘린더/팔레트 `+ 새 업체` | 실제 참가일 preview "금·토 참가 · 12일 · 첫 9/12 · 마지막 10/31" + 미니 달력 | 업체 저장 | 토스트 |
| 전체 일정 변경 | 인스펙터 [계획 편집]만 | 추가/빠지는 날짜 두 열 + Exception 충돌 목록(유지/삭제) | 계획 저장 · +3일 −5일 | 토스트 + 이력 |
| 하루만 변경 | 날짜 셀→업체→[이 날짜만 수정] | 계획 상태 고스트 + 효과 문장 | 10/3 하루만 저장 | 토스트 + 이력 |
| 복원 | 설정/팔레트 [백업에서 복원] | 백업 시각·변경량(엔티티별 ±n)·"현재 상태 스냅샷 저장" 문장 | 현재 상태를 스냅샷으로 저장하고 복원 | 세션 내 복원 취소 |
| 행사 등록 | 팔레트/캘린더 `+ 새 행사` | 기간·장소 요약 한 줄 | 행사 저장 | 토스트 |
| 위젯 이동 | 트레이/컨텍스트 [레이아웃 편집] | 편집 모드 경계·핸들 | Enter 저장 / Esc 취소 | 기본 위치 |

## 업무 시뮬레이션 시나리오 (Playwright)
1. 아침 점검: 위젯 확인 → Layer 1 → 확인 필요 처리(Space) → undo → 재확인.
2. 신규 업체 등록 → 참가일 preview 확인 → 저장 → 캘린더에서 이름 확인.
3. 전체 일정 변경(요일 추가·기간 단축) → diff preview → 충돌 예외 유지 → 저장 → 이력에서 되돌리기.
4. 장날 하루만 불참 → 캘린더 changed 마커·고스트 → 툴팁 문구.
5. 실수 저장 → 토스트 undo → 상태 복귀.
6. 백업 복원 preview → 스냅샷 문장 → 복원 → 복원 취소.
7. 업체 25곳 장날: 월간 셀 2열 → 주 행 성장 → "이 주를 기간표에서 보기" → 기간표 키보드 이동.
8. 위젯 Layout Edit 이동(방향키) → 저장 → 기본 위치.
각 시나리오는 3안(A/B/C 프리셋) 모두에서 실행하고 명령 수·소요 단계를 결과표에 기록한다.
